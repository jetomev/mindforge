# The agreement audit — 2026-11-06

*Why the assistant kept missing agreements on the night of 2026-11-06, what let each miss through, and what mindForge changes so the same kind of miss becomes impossible or visible. Written for the maintainer; public on purpose, like the rest of this repo. Personal details are left out.*

## The night

Seven sessions ran in parallel: a council session that relays the maintainer's decisions, two book rooms, a company-website room, and others. In one of them, in under an hour:

1. Every step the maintainer had to do arrived as a **card** above the prompt, plus a **question box with buttons** at the end of each turn. He never wanted either. His method, months old, is plain chat: a short intro, numbered steps, what he should see, what to send back.
2. The session treated the company as a **books company**. He had said the company is the umbrella over everything, the lead project first, and had to say it twice.
3. A relayed handoff said the company's **domain was "not bought yet"**. It was registered on 2026-09-29. Nobody checked; the check takes one second.
4. A repository about to go public carried the maintainer's **real name beside his pen names**, a **personal-word list in plain text**, and his **personal email as commit author**. Caught before the push, by luck of a careful read.
5. The tone hook flagged a bold line used as a heading **after the reply was already on screen**, so the maintainer read the same long reply twice, minutes after he had been angry about the cards.
6. The session brief repeated the same warnings (unpushed commits in two repos, a stale memory index) for **3–5 sessions running**, and nothing fixed them or escalated.

## Five root causes

### 1. Rules have too many homes, and the newest note wins

A session takes its rules from nine places: the working agreement (L0), three domain rule files (L1), 41 project rule files (L2), **56 "feedback" memory notes** (L3), the one-line summaries in the memory index, the tool descriptions of our own add-ons, the app's own built-in instructions, handoffs relayed from other sessions, and the queue. Nothing ranks them. Nothing checks one against another. A note any session writes at 1 AM is read with the same weight as the agreement the maintainer designed.

That is how a 10-29 note beat a months-old agreement: the add-on's own tool description said "show a step he performs as a card", the index line said "use it for EVERY step he does", and L0 said nothing either way about cards or buttons, so nothing looked like a conflict.

### 2. Memory stores the assistant's paraphrase, not the maintainer's words

Both rule-shaped misses trace to a paraphrase that hardened:

| What he said (from the prompt log) | What memory said | What sessions did |
|---|---|---|
| "do 1, 2, 4, 5" … "looks good!" (picking four add-on ideas) | "use it for EVERY step he does" | a card for every step, for eight days |
| "pi-kognog-azerothcore is not a kognogos app, we will add it to [the company site]" | "[the company site]: the non-KognogOS projects" | treated the company as excluding the lead project |
| (09-28) "use this company for all the digital products"; (10-24) "under everything should be registered" | kept, but below the narrower line, which won | — |

He never said "every step". He never said "only". The assistant did, and wrote it down as if he had.

### 3. Facts have no date and no check

"Both were free on 2026-09-28; buying them is [his] step" sat in the company memory note from 09-28 to 11-06. A to-do written in the present tense reads as a fact forever. It travelled through two relays (council → website room) and arrived as "isn't live yet (buying it is his step)". A public registry lookup answers it in one second.

### 4. Fixes stop short of where the problem lives

- The card was "retired" in memory tonight, but **the add-on is still loaded in every session**, and its tool description still tells the assistant to use it for every step he performs. The rolling next-session plan still says "your-turn card for his steps". The session told the maintainer "the old cards are gone from my instructions". That was not true.
- The "3 sessions, fix it" escalation in `rot` matches a warning's **exact text**, and the text carries a number that changes daily (15, then 17, then 18 unpushed commits). It never reaches three strikes, so it never turns red. The same goes for R7, whose text lists file names that change.
- Corrections are not recorded: `drift.log` has 5 entries, the last from 10-08. Tonight's misses are not in it. The prompt log, meant to be refreshed at every wrap, stopped on 11-03.
- The privacy lesson lives in one project's build script and in mindForge's own pre-commit hook, which each clone must turn on by hand. Nothing global says "a repository going public gets a sweep of every file, its history and its commit identity".

### 5. Rules cut to fit before they were delivered (found 2026-11-06, late)

A second rule system, which a set of helper sessions reads, **trimmed each rule page to its size budget before handing it over**, adding a note that it had been cut. The newest rule, the maintainer's freeze, sat at the end of an over-budget page, so it reached nobody. It wasn't forgotten; it was never delivered. That system's fix: pages always arrive whole, and the budget check still names an oversize page as a problem to trim by hand. Its proof: every helper now receives every line of the shared page and of its own rules, none missing; the same check run against the old cutting would have caught the freeze and four other lines. Repeated copies of a rule stay until the replacement is proven to reach everyone.

Asked of mindForge itself: the always-on list is cut past 10 lines, but loudly. One quiet gap was found. The loader reads only the **first 200 lines or 25 KB** of the memory index, and R9 counted bytes only, so an index of many short lines could be cut below the byte budget without a word. R9 now warns past 180 lines too. Today's index is 124 lines and about 19 KB, under both limits, so it loads whole today; whether anything was cut on an earlier day is not proven.

### The same patterns, found by the helpers' own reviews (2026-11-07)

The second rule system's helpers checked their own pages and found the same shapes in miniature: notes that copied their rules (two homes for one rule), a "settled, don't raise again" list split in two, superseded facts never struck, and instructions still naming a helper and an adviser that had changed. One finding was a real leak: a privacy rule ("private stays private") had no lock in the code path that broke it, so private hand-offs were logged whole into a shared log other helpers read. Fixed the same night: they now go whole to a private, unversioned file, and the shared log keeps a one-line stub; the old entries were moved, with a backup, and a test on a scratch log shows the private text reaches only the private file. **Same lesson as the cut pages: a rule with no guard in the code path it governs is a wish.**

## Each failure: cause and fix

| # | Failure | What let it through | Fix (changes the shape, not the reminder) |
|---|---|---|---|
| 1 | Cards and button boxes | Paraphrase in memory ("every step"); the add-on's own tool description; L0 silent on cards/buttons; the app's built-in push for a question box | Unload the add-on (its description is an instruction no memory can out-vote). One L0 line: no cards, no question box, steps in chat. **New check:** a memory note that states a rule must carry his words and date, and a note that touches an L0 agreement is stopped when it is written. |
| 2 | Company "only books / only non-lead projects" | Paraphrase ("only") outranked his broader words; the old line was left in place below the new one | Same words check. Superseded lines are struck through and marked, never left as live text. |
| 3 | Domain "not bought" | A to-do in present tense; no date; no check; relays repeat it | **Fact checks:** a fact that can be checked carries its check (`mindforge fact`); the brief runs them; a failing one says "memory says X, the world says otherwise". Handoffs mark checked vs. unchecked facts. |
| 4 | Near privacy leak | The lesson lives in one project; the guard is opt-in per clone; issue text skips it (#62) | `mindforge scrub --repo`: every tracked file, the whole history, author and committer identity. A global pre-push guard for repositories that are public or company-owned. Public text (`gh` issues, releases) checked before posting. |
| 5 | Tone flag after the fact | The app has no hook that sees a reply before it is shown; the Stop hook can only force a second reply | Move the check to **before** the reply: a short per-turn note at the moment of writing. The Stop hook stops forcing rewrites; it logs and reminds on the next turn, so he never reads the same reply twice. |
| 6 | The same warnings for days | Escalation keyed on exact text; no way to say "deliberately unpushed" | Key findings by rule and subject, not text. A visible `@local` mark for repos kept local on purpose. A red finding becomes a question for the maintainer in that session's first reply. R7 compares the files' summaries, not their save times. |

### Found in the audit as well

- The rolling next-session plan still prescribes the card, and says the website room "never started".
- The company memory note keeps the superseded line as live text at the bottom, and its summary line still says "named 2026-09-28".
- 17 memory notes carry "waits on [him]" items with no date of when that was last true.
- Backup folders in the project root (`cyberbrawling-empty-objects-…`, `…-git-backup-…`) make R3 report "cannot be read" every session.
- The queue rows for two projects describe a schedule from 11-05 06:00 and have no column 5, so R8 cannot see them.

## What others do (research, 2026-11-06)

About twenty systems were read from their own docs: Claude Code's memory and hooks, Anthropic's context-engineering guidance and memory tool, Cline's Memory Bank, Cursor rules, Kiro steering, AGENTS.md, Aider, Windsurf memories, claude-mem, Basic Memory, Letta/MemGPT, mem0, Zep/Graphiti, ChatGPT memory, instruction-file linters, Google's SRE book on alerts, gitleaks.

- **When a new note contradicts an old one, almost everyone lets the newest win.** mem0 deletes the old note; Zep/Graphiti keeps it with an end date; Letta overwrites in place and protects only read-only blocks. Newest-wins is exactly failure 1. A user's agreement should win on *who said it*, not *when*.
- **Exact words or paraphrase.** Zep keeps the raw messages and links each fact back to them; Letta keeps the history beside the notes. mem0, ChatGPT and Claude Code's own auto memory store a paraphrase. The research literature calls the damage "summarization drift".
- **When a fact was true.** Zep records when a fact became true and when it stopped. Nobody pairs a fact with "last checked" *and* a command that checks it; that part is new here.
- **A hook before the reply is shown.** None exists. `UserPromptSubmit` is the earliest point a hook can act (it adds context before the reply is written); `Stop` runs after, and can only ask for a correction. A display-only hook exists in recent versions, but the assistant never sees what it changes.
- **Alerts** (SRE book): every warning carries the one action that fixes it; a warning ignored for N rounds escalates once to a person; a check that never fires is reviewed for removal.

Ideas taken: provenance-checked memory writes (a `quote:` that must appear in the maintainer's own messages), authority over recency, facts with a check, local git history for the memory folder, the style rule moved before the reply, escalation instead of repetition, a gate before anything goes public.

## What mindForge does about it — the plan

**First, no code** (the maintainer's yes needed):
1. Unload the card add-on.
2. L0 gains three lines: no cards or question boxes; **who said it beats when it was written** (his words in chat, then L0, L1, L2, then notes carrying his words, then the assistant's own notes); a repository going public gets a full privacy sweep.
3. Correct the stale memory: the next-session plan, the company note (domain registered 2026-09-29, the superseded line struck).

**mindForge 0.1.11, "the brain, part 1"** (before Sunday):
1. **Warnings that escalate** — keyed by rule and subject; `@local`; a red finding becomes a question in the first reply. *(built)*
2. **R7 by summary** — no more alarm on every memory save. *(built)*
3. **His words, or it is not a rule** — a `PreToolUse` guard on memory writes: rule-shaped text needs a `quote:` that is found in the maintainer's own messages; a note touching an L0 agreement is refused without one; every note says `source: user` or `source: agent`.
4. **Memory history** — the memory folder becomes a local git repository (never pushed), committed at every session start and wrap: when a rule appeared, and an undo.
5. **The correction catcher** — a `UserPromptSubmit` hook spots a correction ("I never asked", "we discussed this", "again"), logs it to `drift.log`, and tells the assistant to find the broken agreement and fix its source. `wrap` lists the session's corrections.
6. **Tone before the reply** — the same hook puts the three style rules in front of the assistant on each turn. The `Stop` hook stops forcing a second reply; it logs, and the next turn is reminded.
7. **Fact checks** — `mindforge fact add|check|list`: a fact plus the command that proves it; the brief runs them; a failing one says memory and the world disagree.
8. **The privacy gate** — `mindforge scrub --repo` (every tracked file, the whole history, author and committer); a `PreToolUse` gate refuses making a repository public, or posting issue and release text, until the scrub passes (#62).

**Later (v0.2.0, #61):** one log and handoff per machine and per project (#55) matters more now that seven sessions run at once; a report-only consolidation pass at `wrap`.
